# 选择器自愈机制 — 设计方案

> 状态：已实现（`feat/evolution-gate`）。本文件是约束权威，代码与之冲突时以本文件为准。
> 姊妹方案：[落库闸门](./2026-09-19-evolution-gate-design.md)

---

## 1. 问题

UI 回归里最常见的失败不是功能坏了，而是**定位符过期**：前端改了个 class、
换了层容器，选择器就选不中了。用例判红，人去查，发现功能好好的。

这类误报的代价不只是浪费排查时间。**它会训练人忽略红灯** —— 当一半的失败
都是假的，真失败也就没人认真看了。回归套件一旦失去可信度，就等于没有。

## 2. 目标与非目标

**目标**：定位符因页面改版失效时，基于它原本的意图重建定位，让用例继续，
并留下可审阅的修复提案。

**非目标**：
- 不做功能缺陷的自动修复 —— 元素真的不在了就是真缺陷
- 不在测试运行期改写源码
- 不引入 LLM 运行时依赖（不需要 API key，不产生网络调用）

## 3. 安全不变量（唯一不可妥协项）

> **自愈只允许修复「定位」，绝不允许把真失败变成假通过。**

真正的危险不是修不好，而是候选顶替到另一个恰好存在的元素 —— 用例照样绿，
功能其实已经坏了。**误报只是吵，假通过是骗**：它把回归套件从"有时冤枉你"
变成"有时骗你"，后者足以让整套东西失去存在意义。

因此候选必须**同时**满足三条，缺一即放弃自愈、按原样失败：

| 闸 | 判据 | 防的是什么 |
|----|------|-----------|
| ① 意图指纹一致 | 标签 / ARIA role / 可及名称与历史记录吻合 | 顶替到无关元素 |
| ② 全页唯一命中 | 候选在真实页面上 `count() == 1` | 顶替到同类元素中的错误一个 |
| ③ 元素可见 | `is_visible()` 为真 | 命中了隐藏的残留节点 |

## 3.1 拦截时机：反应式，不预探测

自愈**只在操作真正抛出定位失败之后**介入，绝不在操作前探测选择器是否还有效。

实现期踩过的坑（2026-09-19 修正）：早期用 `locator.count() > 0` 做前置探测。
但 **`count()` 不做自动等待** —— SPA 页面尚在渲染时目标元素还没挂载，
预探测把「还没到」误判成「定位失效」，于是在半渲染的页面上启动自愈，
顶替到一个恰好已渲染的无关元素。用例照绿，点的却是别的按钮。
这正是 §3 安全不变量的反面，且是自愈自己制造出来的。

反应式还有一个好处：Playwright 自身的自动等待先跑完，只有它都等不到才算
真的失效 —— 判定依据比任何预探测都强。

配套的代价控制：
- 愈不了的选择器记入失败集，不再重复抓快照（`is_page_loaded()` 这类轮询会
  对同一选择器反复调用，每次抓一遍全页快照代价极高而结论不变）
- 单个页面对象实例的自愈次数上限 25。定位符大面积失效时逐个推断没有意义 ——
  那已不是「某个选择器过期」，而是页面整体变了
- 计数与状态查询（`get_element_count` / `is_enabled` / `is_checked`）不触发自愈：
  返回 0 或 False 是合法答案，当成定位失效会导致在正常页面上乱找元素

## 4. 架构分层

严格遵循既有 POM 分层（`config → conftest → pages → tests`），不新增层级。

| 模块 | 职责 | 是否依赖 Playwright |
|------|------|-------------------|
| `framework/core/healing/engine.py` | 纯逻辑：给定意图与 DOM 快照，算出并排序候选 | **否** |
| `framework/core/healing/runtime.py` | 运行时：抓快照、实跑验证、记录提案、指纹存取 | 否（只调用传入的 page） |
| `framework/core/healing/interceptor.py` | 拦截器：定位失败的统一入口，判定失败类型并调度自愈 | 否 |
| `framework/core/healing/llm.py` | 模型推理后端，规则交白卷时出场 | 否 |
| `framework/core/healing/patcher.py` | 把修复写回 PageObject 源码 | 否 |
| `framework/core/base/base_page.py` | 把所有定位汇聚到 `_locate()`，委派给拦截器 | 是 |
| `framework/conftest.py` | `--self-heal` 开关、终端汇总、strict 退出码 | 否 |

两个核心模块都不 `import playwright`，因此可以用假 page 对象脱离浏览器单测。
这不是洁癖：自愈的判定逻辑是整个机制风险最集中的地方，如果它只能靠跑真实
浏览器来验证，就等于没法充分验证。

`framework/core/base/__init__.py` 采用 PEP 562 惰性导出，使 `core.healing.*` 可在没有
Playwright 的环境里被单测，而不会因导入 `core.base` 被动拉起浏览器依赖。

## 5. 意图从哪来

自愈所依据的「旧有逻辑」有两个来源，互补：

**静态来源 —— PageObject 常量及其注释。** 本项目的 PageObject 骨架约定定位符
写成类顶部常量并带注释：

```python
LOGIN_BUTTON = "#login-btn"   # P0: 登录按钮
```

常量名与注释合起来就是语义说明。`intent_from_source()` 从类源码里解析出来，
并剥离 `P0:` 之类的优先级前缀。

**动态来源 —— 指纹记忆。** 定位符每次成功命中时，记下它选中的元素形态
（标签 / role / 可及名称）存入 `fingerprints.json`。这是自愈判定的主证据。

没有指纹时判定自动收紧（见 §6），因为此时只剩注释可依赖，证据强度不够。

## 6. 候选生成与置信度

| 策略 | 置信 | 稳定性 |
|------|------|--------|
| `data-testid` 等专用测试属性 | 95 | 最高，为测试而设，不随样式变 |
| `id`（非哈希） | 90 | 高 |
| ARIA `role` + 可及名称 | 85 | 高，跟随语义而非样式 |
| 可见文本 | 75 | 中，文案改动即失效 |
| 非哈希类名组合 | 60 | 低，样式重构即失效 |

默认下限 `MIN_CONFIDENCE = 70`，因此类名策略默认不被采纳。
**无指纹时下限提升到 85**，且注释说明必须与元素文本吻合，否则不产出任何候选。

**哈希类名一律排除**（`css-1a2b3c` / `sc-bdVaJa` / `Button_a1b2c3` / 裸十六进制）。
判据与落库闸门 GEN003 同源。拿构建产物当锚点，等于把下一次失效写进代码。

判据采用**定向模式**而非"含数字即哈希"：后者会误杀 `step2`、`tab1` 这类正常
id。误判为哈希只是少一个候选，误判为稳定则会拼出下次构建就失效的选择器 ——
两种代价不对称，故宁可漏判。

## 7. 三种模式

| 模式 | 行为 |
|------|------|
| `off`（默认） | 完全惰性，行为与未引入自愈时逐字一致，零额外开销 |
| `on` | 失效时尝试重建，用例继续；终端逐条列出被修复的定位符 |
| `strict` | 同 `on`，但发生过自愈即让会话以非零码结束 |

**默认必须是 off**：自愈改变了「失败」的含义，不能悄悄生效。CI 建议 `strict`，
让定位符漂移被看见而不是被沉默吸收。

## 8. 产物与写回

运行期只产出两个文件，**绝不改写源码**：

- `reports/self-heal/proposals.jsonl` — 每次自愈尝试的完整记录（意图、全部候选、实际采用者）。**失败的尝试也记录**，因为"找不到任何候选"本身就是"元素真的不在了"的证据。
- `reports/self-heal/fingerprints.json` — 指纹记忆。

写回由 [`selector-self-heal`](../../../skills/selector-self-heal/) skill 承担：
人工复核提案 → 改写 PageObject 常量 → 过落库闸门。

**为什么写回不能自动做**：测试进程里自动改源码，意味着一次跑飞的回归可以
静默重写整个 PageObject 层，而改动淹没在测试输出里没人看见。写回必须是独立、
可审阅、可回滚的一步。

## 9. 失败语义

- **自愈成功 ≠ 干净通过。** 终端汇总显式点名每一处修复。自愈成功说明定位符已经漂移；沉默地放过去，下次就是真失败，而且没人知道从哪一次开始坏的。
- **找不到可靠替代 → 按原样失败。** 不放宽标准硬凑。
- **自愈自身出错 → 不影响测试结论。** 快照抓取、指纹读写、提案记录的任何异常都被吞掉。这与落库闸门的 fail-open 同源：辅助机制不得成为新的失败来源。

## 10. 测试策略

纯逻辑层与运行时层均用 stdlib `unittest`（不用 pytest：`framework/conftest.py` 的
`--env` 为 required 且 import 了 gitignored 的 `config/settings.py`，pytest 无法裸跑）。

```bash
python3 -m unittest discover -s framework/tests/unit -t framework
```

其中 `TestNeverFalsePass` 是机制的红线守卫：它逐条验证角色不符、名称不符、
页面为空、无指纹且说明对不上等场景**一律不产出候选**。**该组变红即表示自愈
可能制造假通过，机制必须停用。**

## 11. 已知限制

- 指纹在首次成功命中后才建立；全新定位符第一次就失效时，只能依赖注释说明，判定收紧到近乎无法自愈。这是有意的：没有证据就不猜。
- 快照上限 400 个元素，超大页面可能漏掉目标。
- 隐式 ARIA 角色只覆盖定位符实际会指向的交互元素（button / a[href] / input 各 type / select / textarea / h1-6 / li / td / th），不是完整的 ARIA 推导表。
  实现期实测修正：页面 JS 中不存在 `element.computedRole`，若只取显式 `role` 属性，
  原生 `<button>` 几乎全部拿不到 role，「role + 可及名称」策略与指纹的 role 维度会**静默失效**；
  且该策略原本拼的是 CSS 属性选择器 `tag[role="button"]`，在真实页面命中 0 个元素且未编码 name，
  现改用 Playwright 的 `role=` 选择器引擎（按隐式角色计算）。
- 候选策略里的文本匹配对国际化页面敏感（切换语言会使文本候选失效）。

## 12. 与落库闸门的关系

两者是同一条原则的两次应用：**自动化产出的东西必须先过校验才能沉淀**。

闸门管的是 agent 写进 `skills/` `rules/` `docs/` 的经验；自愈管的是机器改进
`pages/` 里的定位符。自愈的写回必须过闸门 —— 否则自愈本身就会成为新的垃圾来源。
