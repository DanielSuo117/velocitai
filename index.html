AI Agent 写测试，为什么总是不靠谱？Why Do AI Agents Always Write Unreliable Tests?

没有治理体系的 AI Agent 就像没有规范的新人实习——能写代码，但写出来的测试脆弱、不稳定、无法维护。 An AI Agent without a governance system is like an untrained intern — it can write code, but the tests it produces are brittle, unstable, and unmaintainable.

  • 写出 assert True、assert len(x) > 0 等无效断言Writes useless assertions like assert True or assert len(x) > 0
  • 不理解 SPA 路由切换、新 tab 上下文Doesn't understand SPA route changes or new tab context

HARNESS · 落库闸门Sediment Gate

让自我进化不反噬Keep Self-Evolution From Backfiring

问题 写进 skills / rules / docs 的经验，会被之后每个会话当权威加载 — 一条错的会自我强化。
做法 写入、提交、巡检三个时机校验，4 个维度 17 个违规码。
处置 BLOCK 拒绝并回传修法 · ASK 交人确认 · WARN 放行提示。
底线 闸门自身出故障一律放行，绝不因为自己坏了而挡住你。Problem Lessons written into skills / rules / docs load as authority in every later session — one bad entry reinforces itself.
How Validates at write, at commit and in a full audit; 4 dimensions, 17 violation codes.
Verdicts BLOCK rejects and hands back a fix · ASK defers to you · WARN passes with a note.
Hard line Any internal failure means the write goes through — the gate never blocks you because it broke.

RUNTIME · 选择器自愈Self-Healing

让 UI 改版不再制造误报Stop UI Churn From Faking Failures

问题 定位符被前端构建改没了，用例报红 — 功能其实没坏，只是定位符过期。
做法 操作真正失败后才介入；先按规则重建（testid → id → role+名称），规则交白卷才让模型看页面推断。
处置 候选必须同时过三道闸 — 意图指纹一致、唯一命中、元素可见。
底线 找不到可靠替代就按原样失败，绝不凑一个。Problem A build strips the locator and the test goes red — the feature is fine, the selector is just stale.
How Steps in only after a real failure; rebuilds by rule first (testid → id → role+name), and calls the model only when the rules come back empty.
Verdicts A candidate must clear all three gates — matching intent fingerprint, exactly one match, visible.
Hard line No reliable replacement means the test fails as it would have. Nothing gets forced.

共同底线：宁可什么都不做，也不制造假象。闸门宁可放过一条待改进的沉淀，也不因自身故障挡住你的工作；自愈宁可让用例照常失败，也不顶替到另一个元素让它假通过。两者的失败方向，都朝着安全的那一侧。Shared hard line: do nothing rather than fake something. The gate would rather let an imperfect entry through than block your work over its own bug; healing would rather let the test fail than stand in for some other element and call it green. Both fail toward the safe side.

落库闸门Sediment Gate

落库闸门 · 让沉淀不反噬Sediment Gate · Keep Evolution From Backfiring

自我进化会把经验写进 skills/、rules/、docs/，而这些内容会被之后每一个会话当作高优先级上下文加载。闸门在写入那一刻校验，阻止垃圾进入知识库。Self-evolution writes lessons into skills/, rules/ and docs/ — and every later session loads those as high-priority context. The gate validates at the moment of writing, keeping garbage out of the knowledge base.

⚠️

垃圾沉淀不是静态污染，而是自我强化的循环。一条错误经验被写入后，下个会话会把它当作权威上下文照做，产出更多错误，再沉淀回去。放任不管，agent 会越用越差 — 这正是闸门存在的理由。Bad sediment isn't static pollution — it's a self-reinforcing loop. Once a wrong lesson is written, the next session treats it as authoritative context, produces more errors, and persists those too. Left alone, the agent gets worse with use — which is exactly why the gate exists.

四个校验维度Four Validation Dimensions
EVI

证据门槛 + 语义去重Evidence Threshold + Semantic Dedup

新沉淀必须写明触发条件与失败现象，不能只留一句结论；与既有条款标题重叠过高的，判为重复沉淀。New sediment must state its trigger and the failure it prevents — not just a conclusion. Content overlapping too heavily with existing clauses is flagged as duplicate.

STR

结构合规Structural Compliance

frontmatter 的 name 必须与目录名一致；规则必含 ❌ 反例 + ✅ 正例；篇幅有上限；链接不得指向不存在的文件。Frontmatter name must match the directory; rules must carry a ❌ counter-example and a ✅ example; length is capped; links must not point at missing files.

GEN

通用化检测Genericity Detection

禁止把项目专有域名、本地绝对路径、构建工具生成的哈希类名写进 skill 正文 — 它们换个项目就失效。Project-specific hostnames, local absolute paths and build-tool hash class names are barred from skill bodies — they break on any other project.

REG

BLOCK

直接拒绝写入，并把「修法」回传给 agent，让它自己改对再来。Rejects the write outright and hands the agent a concrete fix, so it can correct itself and retry.

ASK

fail-open 原则：脚本异常、git 超时、输入畸形 — 无论闸门自身出什么故障，一律放行。闸门绝不因为自己坏了而挡住你的工作。Fail-open by design: script errors, git timeouts, malformed input — whatever breaks inside the gate, the write is allowed through. The gate never blocks your work because of its own failure.

选择器自愈Self-Healing

选择器自愈 · 让 UI 微调不再误报Selector Self-Healing · No More False Failures From UI Tweaks

选择器因页面改版失效时，默认行为是判用例失败 — 但这多半是误报：功能没坏，只是定位符过期了。自愈基于该定位符上次成功命中时留下的意图，把它重建出来。When a selector breaks after a UI change the test fails — usually a false alarm: the feature still works, only the locator went stale. Self-healing rebuilds it from the intent recorded the last time it matched.

🛡️

安全底线：自愈只修复「定位」，绝不把真失败变成假通过。真正的危险不是修不好，而是候选顶替到另一个恰好存在的元素 — 用例照样绿，功能其实已经坏了。误报只是吵，假通过是骗。因此候选必须同时满足：意图指纹一致、全页唯一命中、元素可见。任一不满足即放弃自愈，按原样失败。The hard line: self-healing may fix location only — it must never turn a real failure into a false pass. The danger isn't failing to heal; it's a candidate standing in for some other element that happens to exist — the test goes green while the feature is broken. A false alarm is noise; a false pass is a lie. So a candidate must satisfy all three: matching intent fingerprint, exactly one match on the page, and visible. Fail any one and healing is abandoned.

三道闸各防什么What Each Gate Prevents
意图指纹一致Intent Fingerprint

防顶替到无关元素 — 例如把「取消」当成「提交」。Prevents standing in for an unrelated element — e.g. mistaking Cancel for Submit.

全页唯一命中Unique Match

防在同类元素里挑错一个 — 例如页面上有两个「删除」按钮。Prevents picking the wrong one among siblings — e.g. two Delete buttons on the page.

元素可见Visible

防命中隐藏的残留节点 — DOM 里还在，但用户根本看不到。Prevents matching a hidden leftover node — still in the DOM, invisible to the user.

三道闸缺一即放弃自愈，按原样失败。这不是保守，而是因为失败模式不对称：修不好只是回到原状，顶替错了却是用例变绿而功能已坏。Miss any one gate and healing is abandoned — the test fails as it would have. Not conservatism: the failure modes are asymmetric. Failing to heal just restores the status quo; healing to the wrong element turns the suite green while the feature is broken.

意图从哪来Where Intent Comes From

核心思路不是猜「哪个元素长得像」，而是问「这个定位符当初想选中什么」。答案有两个来源，互补。The core idea isn't guessing which element looks similar — it's asking what this locator meant to target in the first place. Two complementary sources answer that.

静态Static · STATIC

常量名 + 注释说明Constant Name + Its Comment

定位符写作 PageObject 类顶部常量，注释即语义 — SUBMIT_BTN = "#submit-order"  # P0: 提交订单。这份说明本来就为人而写，顺手成了机器可读的意图。Locators live as class constants whose comment carries the meaning — SUBMIT_BTN = "#submit-order"  # P0: submit order. Written for humans, it doubles as machine-readable intent.

动态Learned · REMEMBERED

历史指纹Historical Fingerprint

定位符每次成功命中时，顺手记下它选中元素的标签、ARIA 角色与可及名称。这就是「基于旧有的逻辑」 — 失效时据此重建，而不是凭空推测。Every successful match records the element's tag, ARIA role and accessible name. This is the “prior logic” — healing rebuilds from it rather than guessing from scratch.

没有指纹时，判定自动收紧。此时只剩注释一句话，证据不足以认定「页面上这个新元素就是原来那个」— 于是置信下限从 70 抬到 85，且注释必须与元素文本吻合，否则一个候选都不产出。没有证据就不猜。Without a fingerprint, the bar rises automatically. Only the comment remains — not enough to conclude this new element is the old one. The confidence floor goes from 70 to 85 and the comment must match the element's text, or no candidate is produced at all. No evidence, no guessing.

四步重建Four Steps
01

记忆
定位成功时记下命中元素的形态 — 标签、ARIA role、可及名称。这份指纹就是日后自愈所依据的「旧有逻辑」。Remember
On every successful match, record the element's shape — tag, ARIA role, accessible name. That fingerprint is the prior logic healing later relies on.

02

推断
只在操作真正失败之后才介入 — 绝不提前探测，否则 SPA 还没渲染完就会被误判成定位失效。确认确属定位失败，才抓当前 DOM 快照，结合指纹与常量注释还原它本来想选中什么。Infer
Steps in only after an operation genuinely fails — never probing ahead, which would misread a still-rendering SPA as a dead locator. Once it's confirmed a location failure, it snapshots the live DOM and combines fingerprint with the constant's own comment to recover intent.

03

验证
按稳定性排序候选（testid → id → role+名称），逐个在真实页面上实跑，必须唯一命中。Verify
Rank candidates by durability (testid → id → role+name) and actually run each against the live page — must match exactly once.

04

写回
运行期只写提案，绝不改源码；写回由 skill 复核后进行，并同样要过落库闸门。Write back
The run only emits a proposal — it never rewrites source. Write-back happens under review, and must clear the sediment gate too.

规则优先，模型兜底Rules First, Model as Fallback
01 · RULES

规则先上Rules Go First

按稳定性排序拼候选：testid → id → role+可及名称 → 文本 → 稳定类名；构建生成的哈希类名直接跳过 — 拿它当锚点等于把下一次失效写进代码。有稳定锚点摆在那儿时，模型根本不会被调用 — 既慢又贵，结论也不会更好。Candidates are built in order of durability: testid → id → role+accessible name → text → stable class. Build-generated hash classes are skipped outright — anchoring to one just schedules the next breakage. When a stable anchor is right there, the model is never called — slower, costlier, and no better.

02 · MODEL

规则交白卷才轮到模型The Model Only When Rules Come Back Empty

模型拿到的不是「猜一个选择器」，而是失效的定位符、常量名、代码注释里的意图、上次命中元素的形态，以及规则已经试过但不可用的候选。它能做规则做不到的事 — 用结构上下文消歧，例如页面上两个按钮文案完全相同时，给出 main >> role=button[name="登录"]。规则不会拼这种复合选择器。The model isn't asked to guess a selector. It receives the dead locator, the constant's name, the intent from its code comment, the shape of the element that last matched, and every candidate the rules already ruled out. It does what rules cannot — disambiguate by structural context, e.g. returning main >> role=button[name="Login"] when two buttons carry identical labels. Rules never compose selectors like that.

模型只有提名权，没有判决权。它给出的候选必须过与规则候选完全相同的三道闸 — 唯一命中、可见、意图指纹一致。少放行一条，「让模型判断」就成了绕过防假通过保证的后门。没有 API key 时静默退回纯规则模式，不会让任何用例因此失败。The model nominates; it never decides. Every candidate it returns must clear exactly the same three gates as a rule-built one — unique match, visible, matching intent fingerprint. Waive even one and “let the model decide” becomes a backdoor around the no-false-pass guarantee. With no API key it silently falls back to rules only, and no test fails because of it.

四档模式Four Modes
off

默认。行为与未引入自愈时逐字一致，零额外开销。The default. Behaves exactly as before self-healing existed, with zero overhead.

on

失效时尝试重建，用例继续。终端逐条列出被修复的定位符。Attempts a rebuild on failure so the run continues, listing every healed locator in the summary.

strict

同 on，但只要发生过自愈就以非零码结束 — 让 CI 看见定位符漂移。Same as on, but exits non-zero if anything was healed — so CI sees the drift.

auto

同 on，并在规则交白卷时让模型推断，同时把修复写回 PageObject 源码。需要 API key，且会改动工作区文件 — 因此必须显式选择。Same as on, plus the model infers when rules come back empty, and the fix is written back into the PageObject source. Needs an API key and touches files in your working tree — hence opt-in only.

自愈过的用例不算干净通过。自愈成功说明定位符已经漂移；沉默地放过去，下次就是真失败，而且没人知道从哪一次开始坏的。A healed test is not a clean pass. A successful heal means the locator has drifted; let it slide silently and the next run is a real failure nobody can trace back to its start.
