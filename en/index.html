The Problem

Why Are AI Agent-Written Tests Always Unreliable?

An AI Agent without a governance system is like an unsupervised intern — can write code, but produces fragile, unstable, unmaintainable tests.

✕ Bare Agent (No Governance)

  • Uses brittle locators like absolute XPath and hash class names
  • Randomly inserts time.sleep(), blindly adds seconds on timeout
  • Writes meaningless assertions like assert True or assert len(x) > 0
  • Does not understand SPA route transitions or new-tab contexts
  • Repeats the same mistakes with no memory
  • Cross-domain cookie contamination causes batch failures
→

✓ With VelocitAI Governance

  • Six-tier locator priority, P0 ARIA role first
  • Implicit wait by default, explicit timeout only for slow paths
  • Assertions must verify specific content and state
  • Built-in new-tab detection and SPA render-wait rules
  • Hard-won lessons auto-persist to Skills/Rules, never repeated
  • Context isolation strategy eliminates cross-domain contamination
Architecture

POM Four-Layer Separation · Industrial-Grade Architecture

Classic Page Object Model layered design: role-based test splitting, page object inheritance chains, environment config isolation, and automatic Fixture lifecycle management.

tests/ Test Layer

↕
pages/ Page Object Layer
BasePage ← LoginPage ← LandingPage ← … Locators declared as class constants, annotated P0–P5
↕

URLs, tokens, and browser parameters switch by environment (pre / prod)
↕
conftest.py Fixture Layer
browser → context → page → Role-specific base — fully automatic lifecycle management

Rules

4 Rule Domains · 14 Rule Files · Each with ❌ Anti-Pattern + ✅ Best Practice

Covers Agent behavior boundaries, coding conventions, Playwright specifics (8 sub-files), and report strategy. Not suggestions — hard constraints.

🎯

Locator Strategy

  • Six-tier priority: P0 ARIA role → P5 relative XPath
  • Hash class names forbidden (sc-xxx / css-xxx)
  • Absolute XPath forbidden
  • State-class selectors must be anchored with text
  • text= substring matches must be made exact
⏳

Timeout & Wait

  • On timeout, check page URL first, then locator
  • After SPA transition, networkidle ≠ render complete
  • Global implicit wait + explicit timeout only for slow paths
  • time.sleep() forbidden; use Playwright native waits
🧪

Assertion Patterns

  • Page objects contain no assertions (except is_page_loaded)
  • Trivial assertions forbidden (assert True)
  • Search result lists must verify content, not just count
  • Toast/dialog assertions require exact text matching
🌐

Browser Context

  • Session-level shared context forbidden (cross-domain cookie contamination)
  • Same-domain class-level sharing requires three conditions
  • Authentication via URL token runs in isolated context
  • Do not manually manage browser lifecycle
📑

Coding Conventions

  • Classes PascalCase / methods snake_case / constants UPPER_SNAKE
  • Locators declared as class constants, level annotated at end of line
  • Import order: stdlib → third-party → project-local
  • New pages must also be exported in __init__.py
🛡

Agent Behavior Boundaries

  • --env parameter must be confirmed before running tests
  • Git operations (commit/push) require user authorization
  • Do not assume a default environment or silently correct it
  • Ask when documentation and code conflict
📈

Report Strategy

  • Generate HTML report only on failure; skip when all green
  • Marker variable covers all phases (including teardown)
  • Domain stats output regardless of pass/fail
  • Reports auto-rotate to prevent disk accumulation
📏

Performance API Isolation

  • Call clearResourceTimings() immediately after collection
  • Clear must happen inside the same evaluate call
  • Class-level shared context is a high-risk scenario
  • Single test passes but batch fails → check this first
Best Practices

Not Abstract Principles, But Executable Code Standards

Every rule comes with a concrete code comparison — the Agent can automatically avoid anti-patterns, and developers can copy-paste directly.

locator_bad.py
❌ Anti-Pattern 
# Hash class name - changes every build
SUBMIT_BTN = "css=.sc-bdVaJa.dKPpRt"

# Absolute XPath - any DOM change breaks
NAME_INPUT = "/html/body/div[1]/div[2]/input"

# Substring match - hits "Collapse Filter"
FILTER_BTN = "text=Filter"

# Hardcoded sleep - fragile and slow
time.sleep(5)
locator_good.py
✅ Best Practice 
# P0: ARIA role - semantically stable
SUBMIT_BTN = "role=button[name='Submit']"

# P2: data-testid - designed for testing
NAME_INPUT = "[data-testid='name-input']"

# Exact match - no accidental hits
FILTER_BTN = 'text="Filter"'

# Playwright auto-wait - fast and reliable
expect(locator).to_be_visible()
Workflow

From Requirements to Stable Test Cases · 6-Step Closed Loop

The Agent automatically orchestrates tasks according to the Skills routing table. Each step is guarded by a corresponding Skill and Rule.

1

Explore Target Page

Use agent-browser to capture a page DOM snapshot, analyze element structure and available locator strategies. Saves 82–93% of token consumption vs. Playwright MCP.

2

Generate Page Object

Invoke the gen-page-test Skill to automatically generate a PageObject class, including locator constants (annotated P0–P5), action methods, and is_page_loaded().

3

Write Test Cases

Generate regression tests using the add-regression-point and case-round-trip Skills, ensuring round-trip closure and consistent state.

4

Run & Debug

Execute tests via test-runner; on failure quick-debug automatically applies three-step triage: confirm page → check tab → inspect locator.

5

Code Review

The code-reviewer agent reviews at P0/P1/P2 severity levels, combining AST knowledge graph analysis of change impact radius and test coverage.

6

Knowledge Evolution

Hard-won lessons are automatically written into Skills / Rules / Docs — the Agent's "muscle memory" continuously evolves, so the same problem never recurs.

Installation

Multi-Platform One-Click Install

Native Claude Code plugin install, or manual integration into any AI Agent project.

Claude Code 
# One-line plugin install
$ claude install-plugin velocitai

# Or manual setup
$ git clone https://github.com/DanielSuo117/velocitai.git
$ cp -r velocitai/{skills,rules,hooks,docs,.claude,CLAUDE.md} \
    your-project/
Copilot / Gemini / Others 
# Clone and integrate
$ git clone https://github.com/DanielSuo117/velocitai.git
$ cp -r velocitai/{skills,rules,hooks,docs,CLAUDE.md} \
    your-project/

# Copilot CLI — also copy AGENTS.md
$ cp velocitai/AGENTS.md your-project/

# Gemini CLI — also copy GEMINI.md
$ cp velocitai/GEMINI.md your-project/
Setup & Run 
# Install dependencies & browser
$ cd your-project
$ python -m venv .venv && source .venv/bin/activate
$ pip install -r requirements.txt
$ playwright install chromium

# Run tests (--env is REQUIRED, agent will ask if not specified)
$ pytest tests/ --env=pre

# View report
$ allure serve reports/allure-results
