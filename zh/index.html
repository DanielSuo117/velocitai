问题所在

AI Agent 写测试，为什么总是不靠谱？

没有治理体系的 AI Agent 就像没有规范的新人实习——能写代码，但写出来的测试脆弱、不稳定、无法维护。

✕ 裸 Agent（无治理）

  • 使用绝对 XPath、哈希类名等脆弱定位符
  • 随意 time.sleep()，超时后盲目加秒
  • 写出 assert True、assert len(x) > 0 等无效断言
  • 不理解 SPA 路由切换、新 tab 上下文
  • 同样的错误反复出现，没有记忆
  • 跨域 cookie 污染导致批量失败
→

✓ VelocitAI 治理后

  • 六级定位符优先级，P0 ARIA role 优先
  • 隐式等待为主，仅慢路径用显式 timeout
  • 断言必须验证具体内容和状态
  • 内置新 tab 检测、SPA 渲染等待规则
  • 踩坑后自动沉淀到 Skills/Rules，永不复犯
  • context 隔离策略，消除跨域污染
架构

POM 四层分离 · 工业级架构

经典 Page Object Model 分层设计，按角色拆分测试、页面对象继承链、环境配置隔离、Fixture 自动管理。

tests/ 测试层
按角色拆分文件：test_<role>_flow.py — 每个测试类继承 Base 或 Role-Base
↕
pages/ 页面对象层
BasePage ← LoginPage ← LandingPage ← … 定位符声明为类常量，标注 P0–P5 级别
↕
config/ 配置层
URL、Token、浏览器参数按环境（pre / prod）切换
↕
conftest.py Fixture 层
browser → context → page → Role-specific base — 全自动生命周期管理

路由
规则

4 大规则域 · 14 个规则文件 · 每条配 ❌ 反例 + ✅ 正例

覆盖 Agent 行为边界、编码规范、Playwright 专项（8 个子文件）和报告策略。不是建议，是红线。

🎯

定位符策略

  • 六级优先级：P0 ARIA role → P5 相对 XPath
  • 禁止哈希类名（sc-xxx / css-xxx）
  • 禁止绝对 XPath
  • 状态类 selector 必须配 text 锁定
  • text= 子串匹配必须精确化处理
⏳

超时 & 等待

  • 超时先排查页面 URL，再查定位符
  • SPA 切换后 networkidle ≠ 渲染完成
  • 全局隐式等待 + 仅慢路径显式 timeout
  • 禁止 time.sleep()，使用 Playwright 原生等待
🧪

断言模式

  • 页面对象不包含断言（is_page_loaded 除外）
  • 禁止无效断言（assert True）
  • 列表搜索结果要验证内容不只验证数量
  • Toast/弹窗需带文本精确匹配
🌐

浏览器上下文

  • 禁止 session 级共享 context（跨域 cookie 污染）
  • 同域 class 级共享需满足三个条件
  • 认证通过 URL token 独立执行
  • 不手动管理浏览器生命周期
📑

编码规范

  • 类 PascalCase / 方法 snake_case / 常量 UPPER_SNAKE
  • 定位符声明为类常量，行尾标注级别
  • 导入顺序：标准库 → 第三方 → 项目内
  • 新页面必须同步导出到 __init__.py
🛡

Agent 行为边界

  • 运行测试前必须确认 --env 参数
  • Git 操作（commit/push）需用户授权
  • 禁止自行默认环境或无声纠偏
  • 文档与代码冲突时必须询问
📈

报告策略

  • 仅失败时生成 HTML 报告，全绿跳过
  • 标记变量覆盖全阶段（含 teardown）
  • 域名统计无论通过与否都输出
  • 报告自动轮转，避免磁盘堆积
📏

Performance API 隔离

  • 收集后立即 clearResourceTimings()
  • 清空必须在同一次 evaluate 内部
  • class 级共享 context 是高危场景
  • 单独通过 + 批量失败 → 首查此项
最佳实践

不是抽象原则，是可执行的代码规范

每条规则都给出具体的代码对照 —— Agent 看到反例就能自动规避，开发者也能直接 copy-paste。

locator_bad.py
❌ 反模式 
# 哈希类名 — 每次构建都会变化
SUBMIT_BTN = "css=.sc-bdVaJa.dKPpRt"

# 绝对 XPath — DOM 结构变化即失效
NAME_INPUT = "/html/body/div[1]/div[2]/input"

# 子串匹配 — 会命中"收起筛选"等按钮
FILTER_BTN = "text=Filter"

# 硬编码等待 — 脆弱且低效
time.sleep(5)
locator_good.py
✅ 最佳实践 
# P0: ARIA role — 语义稳定
SUBMIT_BTN = "role=button[name='Submit']"

# P2: data-testid — 专为测试设计
NAME_INPUT = "[data-testid='name-input']"

# 精确匹配 — 不会误命中
FILTER_BTN = 'text="Filter"'

# Playwright 自动等待 — 快速可靠
expect(locator).to_be_visible()
工作流

从需求到稳定用例 · 6 步闭环

Agent 按照 Skills 路由表自动编排任务。每一步都有对应的 Skill 和 Rule 保驾护航。

1

探索目标页面

使用 agent-browser 获取页面 DOM 快照，分析元素结构和可用的定位策略。相比 Playwright MCP 节省 82–93% 的 token 消耗。

2

生成 Page Object

调用 gen-page-test Skill，自动生成 PageObject 类，包含定位符常量（标注 P0–P5）、操作方法和 is_page_loaded()。

3

编写测试用例

基于 add-regression-point 和 case-round-trip Skills 生成回归测试，确保用例往返闭合、状态一致。

4

运行 & 调试

通过 test-runner 执行测试，失败时 quick-debug 自动按三步法排查：确认页面 → 检查 tab → 查定位符。

5

代码审查

code-reviewer 代理按 P0/P1/P2 分级审查，结合 AST 知识图谱分析变更影响半径和测试覆盖率。

6

沉淀进化

踩坑后自动将经验写入 Skills / Rules / Docs — Agent 的「肌肉记忆」持续进化，同类问题不再复现。

安装

多平台一键安装

Claude Code 原生插件安装，或手动集成到任意 AI Agent 项目。

Claude Code 
# 一行命令安装插件
$ claude install-plugin velocitai

# 或手动安装
$ git clone https://github.com/DanielSuo117/velocitai.git
$ cp -r velocitai/{skills,rules,hooks,docs,.claude,CLAUDE.md} \
    your-project/
Copilot / Gemini / 其他平台 
# 克隆并集成
$ git clone https://github.com/DanielSuo117/velocitai.git
$ cp -r velocitai/{skills,rules,hooks,docs,CLAUDE.md} \
    your-project/

# Copilot CLI — 同时复制 AGENTS.md
$ cp velocitai/AGENTS.md your-project/

# Gemini CLI — 同时复制 GEMINI.md
$ cp velocitai/GEMINI.md your-project/
安装 & 运行 
# 安装依赖和浏览器
$ cd your-project
$ python -m venv .venv && source .venv/bin/activate
$ pip install -r requirements.txt
$ playwright install chromium

# 运行测试（--env 必须指定，未指定时 Agent 会询问）
$ pytest tests/ --env=pre

# 查看报告
$ allure serve reports/allure-results
